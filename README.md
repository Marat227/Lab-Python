## Описание

**SodiumFlow** — программное обеспечение для измерения расхода жидкого натрия
в контуре жидкометаллического теплоносителя (реакторы типа БН). Система
регистрирует заряженные частицы в потоке двумя разнесёнными датчиками,
вычисляет скорость потока методом кросс-корреляции и определяет текущий
расход через среднеквадратичное отклонение сигнала.

### Ключевые особенности

| Параметр | Значение |
|---|---|
| АЦП | 2× ADS1115, 16 бит, ±6.144 В (PGA 2/3) |
| Эффективная частота | 10 000 выборок/с (предиктор) |
| Реальная частота АЦП | 860 выборок/с |
| Расстояние между датчиками | 15 см |
| Метод измерения | Кросс-корреляция + СКО |
| Платформа | ПК, I2C-адаптер (USB) |
| GUI | Tkinter + Matplotlib |

## Физический принцип

```
Труба с жидким натрием
═══════════════════════════════════════════════════════════►  поток

   [Зарядка          [Датчик 1]            [Датчик 2]
    частиц]          (ADS1115 #1)          (ADS1115 #2)
       │             0x48, AIN0            0x49, AIN0
       ▼                  │                     │
   Электрический          ▼                     ▼
   импульс            s₁(t)                 s₂(t)
                          │                     │
                          └──────┬──────────────┘
                                 ▼
                    Кросс-корреляция R₁₂(τ)
                                 │
                    ┌────────────┼────────────┐
                    ▼            ▼            ▼
              τ (задержка)   v = L/τ     σ → Q(расход)
```

### Математическая модель

**1. Кросс-корреляция → скорость:**

```
R₁₂(τ) = ∫ s₁(t) · s₂(t + τ) dt

v = L / τ_max    где L = 0.15 м
```

**2. СКО → расход:**

```
σ = √( 1/N · Σ(xᵢ - x̄)² )

Q = 1.2·σ² + 2.1·σ + 5.0    (калибровочный полином)
```

**3. RMS → загрузка металлом:**

```
RMS = √( 1/N · Σxᵢ² )
```

## Система фильтрации

Каскадная система из 5 независимых валидаторов с взвешенной агрегацией:

```
Сырой сигнал
    │
    ▼
┌─────────────────────┐  Вес: 15%
│  Bandpass Filter    │  Удаление drift и ВЧ шума
│  (Butterworth 4-го) │  10–2000 Гц
└─────────┬───────────┘
          ▼
┌─────────────────────┐  Вес: 15%
│  Outlier Detector   │  IQR + Z-score
│                     │  Выбросы от помех
└─────────┬───────────┘
          ▼
┌─────────────────────┐  Вес: 20%
│  Spectral Validator │  Наличие характерных
│                     │  пиков в спектре
└─────────┬───────────┘
          ▼
┌─────────────────────┐  Вес: 30%
│  Correlation Valid. │  Высота, острота, SNR
│                     │  пика кросс-корреляции
└─────────┬───────────┘
          ▼
┌─────────────────────┐  Вес: 20%
│  Temporal Checker   │  Согласованность
│                     │  скорости во времени
└─────────┬───────────┘
          ▼
┌─────────────────────┐
│  Decision System    │
│                     │
│  confidence =       │
│    Σ(score × weight)│
│                     │
│  ≥ 0.7 → ACCEPT    │
│  < 0.7 → REJECT    │
└─────────────────────┘
```

### Что фильтруется

| Тип помехи | Метод обнаружения |
|---|---|
| Сетевая наводка 50 Гц | Bandpass + Spectral |
| Импульсные помехи от реле | Outlier (Z-score) |
| Дрейф нуля АЦП | Bandpass (HPF) |
| Сигналы от соседних приборов | Spectral + Correlation |
| Кавитационные всплески | Temporal + Outlier |
| Электромагнитные наводки | Spectral + Bandpass |

## Предиктор АЦП

ADS1115 физически выдаёт **860 SPS**. Для достижения **10 000 SPS** используется
ансамбль из трёх методов интерполяции:

| Метод | Основа | Преимущества |
|---|---|---|
| **Котельников** | sinc-интерполяция | Теоретически идеален для bandlimited |
| **Полином** | polyfit 3-го порядка | Быстрый, гладкий |
| **Сплайн** | Кубическая аппроксимация | Хорошая локальная точность |

```
Реальные отсчёты (860 SPS):
  ●───────────●───────────●───────────●

Предсказанные (10 000 SPS, ×11):
  ●──○──○──○──○──○──○──○──○──○──○──●──○──○──○──○

  ○ = ансамбль(Kotelnikov, Poly, Spline) / 3
```

## 🔧 Обработка ошибок

### Механизмы

| Механизм | Описание | Где применяется |
|---|---|---|
| **Retry + Backoff** | Повтор до 3 раз с экспоненциальной задержкой | Чтение I2C |
| **Circuit Breaker** | Блокировка после 5 ошибок на 10 с | Драйвер АЦП |
| **Graceful Degradation** | Переключение режимов: full → degraded → minimal → offline | Глобально |
| **Error Handler** | Перехват исключений с возвратом значения по умолчанию | Все вычисления |

### Пример работы Circuit Breaker

```
Попытка 1: I2C error → retry через 0.1 с
Попытка 2: I2C error → retry через 0.2 с
Попытка 3: I2C error → retry через 0.4 с
Ошибка: Circuit OPEN → блокировка на 10 с
...
Через 10 с: Circuit HALF_OPEN → пробная попытка
Успех: Circuit CLOSED → нормальная работа
```

## Калибровка

### Процедура

1. Установите известный расход через эталонный расходомер
2. Запишите значение σ (СКО сигнала)
3. Повторите для 5–10 точек в рабочем диапазоне
4. Аппроксимируйте полиномом: `Q = a·σ² + b·σ + c`
5. Внесите коэффициенты в `config.py`:

```python
CALIBRATION_POLY = [a, b, c]
```

## Миграция с FBD

### Соответствие блоков

| FBD-блок (IEC 61131-3) | Python-эквивалент | Модуль |
|---|---|---|
| `ADC_READ` | `ADS1115Driver.read_voltage()` | `adc/driver.py` |
| `PREDICTOR` | `EnsemblePredictor.predict()` | `adc/predictor.py` |
| `BPF_FILTER` | `BandpassFilter.filter()` | `filtering/bandpass.py` |
| `X_CORR` | `cross_correlate()` | `processing/correlation.py` |
| `RMS_CALC` | `compute_rms()` | `processing/statistics.py` |
| `STD_CALC` | `compute_std()` | `processing/statistics.py` |
| `CALIBRATE` | `std_to_flow()` | `processing/calibration.py` |
| `LIMIT_CHECK` | `DecisionSystem.make_decision()` | `filtering/decision_system.py` |
| `HMI_DISPLAY` | `FlowmeterGUI.update_data()` | `gui/main_window.py` |
| `DATA_LOG` | `DataLogger.log()` | `logging_system/data_logger.py` |

### Отличия от оригинала

| Аспект | FBD (STM32) | Python (ПК) |
|---|---|---|
| Детерминизм | Жёсткий цикл, мкс | GIL, GC, не real-time |
| Частота | Нативная 10 kSPS | 860 SPS + предиктор |
| Надёжность | Промышленный ПЛК | Circuit Breaker + Retry |
| Фильтрация | Базовая | Каскадная, 5 уровней |
| Визуализация | HMI-панель | Matplotlib в реальном времени |

## Устранение неполадок

### АЦП не обнаруживается

```bash
# Проверить подключение:
sudo i2cdetect -y 1

# Проверить права:
ls -la /dev/i2c-*
# Должно быть: crw-rw---- 1 root i2c ...

# Добавить пользователя в группу:
sudo usermod -aG i2c $USER
```

### Высокий уровень шума

- Увеличьте `BUTTERWORTH_ORDER` в `config.py`
- Сузьте `BANDPASS_LOW` / `BANDPASS_HIGH`
- Проверьте экранирование кабелей датчиков

### Ложные срабатывания

- Увеличьте `DECISION_CONFIDENCE_THRESHOLD` (например, до 0.8)
- Увеличьте `CORRELATION_MIN_PEAK`
- Проверьте `TEMPORAL_MAX_DEVIATION`

### GUI тормозит

- Увеличьте `UPDATE_INTERVAL_MS` (например, до 200)
- Уменьшите `CORRELATION_WINDOW`
