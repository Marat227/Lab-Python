# SodiumFlow Next 1.0

Полностью переписанное настольное приложение для анализа задержки двух синхронно регистрируемых сигналов и оценки расхода. **Демонстрационный/исследовательский прототип, не сертифицированный расходомер и не система безопасности реактора.**

## Установка и запуск (Windows 10/11 x64)

1. Установите Python 3.12 x64.
2. Откройте командную строку в папке проекта:

```bat
py -3.12 -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python run.py
```

При первом запуске выберите «Симуляция» и нажмите «Запустить».

## Сборка EXE

Запустите `build_windows.bat` на компьютере под Windows. Скрипт установит зависимости, выполнит тесты и соберёт `dist\SodiumFlowNext.exe`. В репозитории также есть GitHub Actions workflow с ручным запуском `workflow_dispatch`, публикующий EXE как артефакт. Сборка на Windows обязательна для корректного Windows EXE.

## Возможности

- Тёмный интерфейс PySide6 + pyqtgraph; тренды двух каналов, нормализованная кросс-корреляция, спектр, крупные показания.
- Воспроизводимая симуляция потока с контролируемой задержкой и шумом.
- Реплей CSV (`time_s,ch1_v,ch2_v`), запись текущей сессии CSV.
- Опциональный последовательный источник с форматом строки `time_s,ch1_v,ch2_v` (baud 230400): подходит **только** для внешнего микроконтроллерного моста с данным протоколом.
- Установка расстояния датчиков, диаметра, частоты, полосы фильтрации и допустимого диапазона скорости.
- Тестируемое чистое ядро `sodiumflow/core.py`.

## Математика и физические ограничения

Два сигнала регистрируются синхронно с частотой `fs`. После удаления линейного тренда и цифровой полосовой фильтрации находится максимум `corr(ch2, ch1)` **только на положительных задержках** в пределах `L/vmax ... L/vmin`. Нормированная корреляция по выровненным парам проверяется на порог. Величина задержки уточняется параболической аппроксимацией пика; эта оценка **не повышает частоту АЦП**. Скорость: `v=L/delay`. Объёмный расход при предположении равномерного профиля скорости: `Q=v*pi*(D/2)^2*3600*k` в м³/ч, где `D` в метрах и `k` — экспериментально получаемый поправочный коэффициент. **Без калибровки и подтверждения модели это только инженерная оценка.**

При низкой корреляции данные отображаются как недостоверные, вместо подстановки вымышленных чисел. Частота дискретизации, в отличие от интерполированных значений, всегда реальная. Нельзя корректно определять скорость, если искомая задержка меньше одного периода отсчёта или каналы не синхронизированы.

## Оборудование

Сами ADS1115 с USB-переходником не имеют универсального Windows протокола. В приложении **нет обещания прямого подключения «любого USB–I²C адаптера»**. Выберите мост, который выдаёт синхронные пары с временными метками в CSV-строках, или напишите драйвер под точную модель адаптера. ADS1115 ограничен максимальной заявленной частотой 860 SPS на устройство; по USB/И²С реальная скорость и синхронность двух отдельных модулей должны быть проверены на стенде. Показанный в интерфейсе режим «Serial» не гарантирует частоту 860 SPS при ASCII и 230400 бод без проверки пропускной способности.

## Данные

CSV — напряжения в вольтах и время в секундах. Текущий драйвер последовательного потока предполагает одинаковые интервалы; неравномерные временные метки нужно предварительно ресемплировать и проверить. В буфер попадают полученные пары, а не прогнозные отсчёты. На экране используется последнее окно сигнала. Поле «Расход» — вычисленный объёмный расход, а не непосредственное измерение.
